# Reading the recipe / item / fluid graph (automatic pricing)

Verified against Factorio 2.1.24 runtime + prototype API and `wube/factorio-data` 2.1.24.

## Where to compute prices

| Option | When | Pros | Cons |
|---|---|---|---|
| **Runtime** (`prototypes.*`) in `on_init` + `on_configuration_changed` | Default | Sees the final graph after every mod's `data-final-fixes`; result stored in `storage`, per force if needed; easy to recompute | Runs in a tick: must stay fast or be spread over ticks for huge modpacks |
| `data-final-fixes.lua` (`data.raw`) | Only if prices must change prototypes (descriptions, generated recipes) | Can write `mod-data` / localised descriptions | Mods sorted after us may still edit recipes in their own `data-final-fixes`; raw data is un-normalised (many shorthand forms from older mods, `results` may be nil) |

Recommended: hand-tuned **seed prices** for raw resources in a `mod-data` prototype (other mods can
patch it in `data-updates`), then propagate through recipes at runtime. Recompute in
`on_configuration_changed` (fires when any mod, prototype or startup setting changed).

## Runtime API used (all verified)

- `prototypes.recipe[name]` → `LuaRecipePrototype`: `ingredients` (array of `Ingredient`:
  `type` = `"item"|"fluid"`, `name`, `amount`), `products` (array of `Product`: `type`, `name`,
  `amount` **or** `amount_min`+`amount_max`, `independent_probability`, `shared_probability`,
  `extra_count_fraction`, `ignored_by_productivity`, `ignored_by_stats`, fluid `temperature`),
  `main_product`, `energy` (seconds), `categories` (array, **2.1**), `has_category(name)`, `enabled`
  (initially enabled), `hidden`, `parameter`, `allow_decomposition`, `allow_as_intermediate`,
  `surface_conditions`, `get_product_amount(index, productivity?)`.
- `prototypes.item[name]` → `LuaItemPrototype`: `stack_size`, `weight`, `spoil_result`,
  `burnt_result`, `place_result`, `fuel_value`, `hidden`, `parameter`.
- `prototypes.fluid[name]` → `LuaFluidPrototype`: `default_temperature`, `max_temperature`,
  `fuel_value`, `hidden`, `parameter`.
- `prototypes.quality[name]` → `LuaQualityPrototype`: `level`, `next`, `previous`, `next_probability`.
- `prototypes.entity[name].mineable_properties.products` (resources: filter
  `prototypes.get_entity_filtered({{filter = "type", type = "resource"}})`), `prototypes.tile[name].fluid`
  (offshore water etc.) — the graph's leaves.
- `prototypes.get_recipe_filtered({{filter = "has-product-item", elem_filters = {{filter = "name", name = "iron-plate"}}}})`
  for reverse lookups; other filters: `"category"`, `"hidden"`, `"has-ingredients"`, `"has-products"`,
  `"enabled"`, `"subgroup"`, `"energy"`.
- `prototypes.mod_data[name].data` (from a `mod-data` prototype).

`LuaCustomTable` iteration with `pairs` is deterministic; but **build your own sorted arrays of names**
before running a fixed-point algorithm so results do not depend on prototype order.

## Algorithm sketch (cycle-safe)

1. Collect leaves: resources (mining products), tile fluids, items with no producing recipe → seed price
   (mod-data or setting-derived default), else mark "unpriceable".
2. Build `producers[item] = {recipe, ...}` excluding:
   - recipes with `has_category("recycling")` (generated by the `recycler` mod: `<item>-recycling`,
     returns ~25% of ingredients → reverse edges that create cycles),
   - `hidden` or `parameter` recipes (still allow hidden ones explicitly whitelisted),
   - barrel fill/empty (`allow_decomposition == false` is a good signal; base marks barrel recipes so),
   - void/incinerator style recipes with no products.
3. Price(item) = min over producers of
   `(Σ ingredient price × amount + energy × time_cost) / expected_output(item)`, where expected output
   uses `amount` or `(amount_min+amount_max)/2`, × `independent_probability` (default 1),
   + `extra_count_fraction`.
4. Iterate to a fixed point with a max iteration count (Bellman-Ford style); anything not converged is
   "unpriceable" and must be handled gracefully (not tradeable).
5. Spoilage (`spoil_result`) and burnt results are not production edges; ignore them for price, but you
   may discount spoilable items.
6. Quality: price a quality variant as `base_price × f(level)`; never multiply the graph by quality.

Store results as `storage.prices[name] = number` (shared economy) or per force
`storage.forces[force_index].prices` if forces can diverge (dynamic supply/demand).

## Space Age / optional-mod specifics

- Dependency `? space-age` only orders loading; Space Age can still be absent at runtime.
- In 2.1 `space-age` requires `base`, `elevated-rails`, `recycler`; it **recommends** `quality`.
  `quality` requires `recycler`. So:
  - recycling recipes exist iff `script.active_mods["recycler"]` (data stage: `mods["recycler"]`);
  - quality tiers beyond normal exist iff `script.feature_flags.quality`;
  - planets/platforms exist iff `script.feature_flags.space_travel` / `script.active_mods["space-age"]`.
- Recycling recipes are generated in `recycler/data-updates.lua` for every recipe
  (`<recipe-results>-recycling`) and for every item without one (`<item>-recycling`, self-recycle
  with `independent_probability = 0.25`), skipping items with `auto_recycle = false`, `parameter`
  items and names containing `-barrel`. They exist by the time our `data-final-fixes` runs.
  **Set `auto_recycle = false` on credit/token items** we create.
- Planets: `game.planets` (`LuaPlanet` by name), `surface.planet` (nil on platforms),
  `surface.platform` (`LuaSpacePlatform` on platforms), `prototypes.space_location` (planets are a subtype),
  `force.platforms`. Recipes may have `surface_conditions` (e.g. pressure/gravity) — a recipe that cannot
  run anywhere the force can reach should not set a price.
- Space Age science packs, biter eggs, spoilables (`spoil_result`, `get_spoil_ticks(quality)`): treat
  as normal items but consider spoil time in pricing/delays.
- Item weight (`LuaItemPrototype.weight`, rocket capacity) is a ready-made "transport cost" proxy for
  logistics tiers.

```lua
  end
end
for type_name in pairs(defines.prototypes.item) do        -- all item-like prototype types
  for name, item in pairs(data.raw[type_name] or {}) do --[[ ... ]] end
end
```

`defines.prototypes.item` lists every item subtype (`item`, `tool`, `module`, `ammo`, `capsule`,
`armor`, `gun`, `item-with-entity-data`, ...): **items are not only in `data.raw.item`**. The recycler
mod iterates exactly this way.

## Determinism notes

- The pricing pass must be a pure function of prototypes + settings + storage so every client computes
  the same result; never cache it in a file-scope local that is filled outside `on_init` /
  `on_configuration_changed` / events (see factorio-runtime).
- Floating point is deterministic in Factorio (custom math functions), but keep prices as numbers
  rounded to a fixed precision before writing them to circuit signals (int32).
