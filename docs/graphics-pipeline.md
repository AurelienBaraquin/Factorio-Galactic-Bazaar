# Graphics pipeline

How the mod's sprites and icons are made, checked and wired into the prototypes. What they look like
and why: [visual-identity.md](visual-identity.md). Why this pipeline:
[ADR-0027](adr/0027-procedural-blender-render-pipeline.md).

Every image under `graphics/` is rendered from a procedural model written in Python; nothing is
drawn by hand and no image generator is used. The same script gives the same files, byte for byte.

## Files

| Path | What it is | Ships |
|---|---|---|
| `tools/graphics/setup-blender.sh` | installs the pinned Blender | no |
| `tools/graphics/render.py` | render driver: builds each model, renders, crops, writes the PNGs, the manifest and `prototypes/sprites.lua` | no |
| `tools/graphics/gbrender/scene.py` | camera, lights, render settings, main and shadow passes | no |
| `tools/graphics/gbrender/parts.py` | palette, materials, primitives (box, cylinder, cone, torus, sphere, extruded plate, arrow) | no |
| `tools/graphics/gbrender/png.py` | PNG writer (zlib level 9, per-row filter choice), cropping, sheets, icon mipmaps | no |
| `tools/graphics/gbrender/models/` | the models: `common.py` (the 1×1 crate, the 2×2 plinth, the `Model` description), one file per family (`trading.py`, `logistics.py`, `finance.py`) | no |
| `tools/graphics/manifest.json` | sizes and shifts of every render, merged across runs so one model can be re-rendered alone | no |
| `graphics/entity/<name>/<name>.png`, `<name>-shadow.png` | the building (or its animation sheet) and its shadow | yes |
| `graphics/icons/<name>.png` | the item icon with its mipmaps | yes |
| `prototypes/sprites.lua` | generated: file, size, shift, frames of each layer, icon file | yes |
| `prototypes/graphics.lua` | turns those descriptions into Factorio `Sprite`, `Animation` and icon tables | yes |
| `spec/graphics_spec.lua` | the check (see [Check](#check)) | no |

## Install Blender

```bash
tools/graphics/setup-blender.sh     # once; idempotent
```

It installs the official portable Linux build of **Blender 4.5.15 LTS** under
`~/.local/opt/blender-4.5.15/` (outside the repository, never committed), with no root access. The
archive's SHA256 is pinned in the script and also checked against Blender's published checksum file;
either mismatch stops it. The download is about 380 MB, the installed folder about 1.2 GB. Rendering
runs headless (`--background`), so WSL needs no display or GPU.

## Render

```bash
BLENDER=~/.local/opt/blender-4.5.15/blender
$BLENDER --background --factory-startup --python tools/graphics/render.py              # every model
$BLENDER --background --factory-startup --python tools/graphics/render.py -- gb-hub    # one model
```

A full render takes about 4 minutes on 6 CPU threads; the two animated 2×2 buildings take most of it.
After a render, run the checks (below), look at the result in the game, and commit the changed
PNGs together with `prototypes/sprites.lua` and `tools/graphics/manifest.json`.

To add a building: write its `build(frame)` function in the family file, append a `Model(name,
size, build, frames=...)` to that file's `MODELS`, render it, and use `graphics.sprite(name)` (or
`graphics.animation(name)`) and `graphics.icons(name)` in its prototype.

## Projection, light and conventions

| Convention | Value | How it was checked |
|---|---|---|
| Resolution | 64 px per tile, drawn at `scale = 0.5` (the game's high-resolution sprites; 2.x ships only these) | base steel chest: 64 px wide at scale 0.5; accumulator 130 px for 2 tiles |
| Camera | orthographic, no yaw, pitched 45° below the horizon, no vertical stretch; north is up | the accumulator's round tops are ellipses about 0.7 as high as wide (cos 45° ≈ 0.71); a 64-px-wide steel chest only fits its 37-px top and 32-px front with a 45° pitch |
| Placement | the selection box's south edge lands on the tile's south edge; `render.py` computes each layer's `shift` from the crop | base steel chest and accumulator bottoms sit on their tiles' south edges with their shifts |
| Sun | from the west, 11° towards the north, 40° high, slightly warm; shadowless fill light from the viewer's side in the main pass, warm grey ambient | a crate's shadow (size and shift in `tools/graphics/manifest.json`, regenerated by each render) falls in the same direction and about as far as the base steel chest's, 110 × 46 px at shift (0.38, 0.25) |
| Shadow layer | separate file, `draw_as_shadow = true`, black with the shadow's coverage in alpha (the game sets its opacity, as with base shadows, which are opaque black) | the shadow pass hides the model from the camera and catches its shadow on an invisible ground plane |
| Animations | one sheet per layer, 8 frames per row (`line_length`), shadow animated with the building | `frame_count`, `line_length`, `animation_speed`, `run_mode` come from the model |
| Icons | rendered at 256 px framed on the model, reduced to 64, 32, 16 and 8 px side by side (120 × 64 file); the game infers the mipmap count from the file's width (`icon_mipmaps` was removed in 2.0, see the game's changelog) | 2.1 prototype docs (*IconData*: "If an icon file contains mipmaps then the game will automatically infer the icon's mipmap count") |
| Colour | Blender's Standard view transform, sRGB 8-bit PNG, straight alpha (the game premultiplies on load) | — |

Side-by-side comparisons with the base steel chest and accumulator were made while choosing these
values; the in-game check is listed below.

## Reproducibility

Cycles on the CPU with a fixed seed (0), 64 samples per pixel, no adaptive sampling and no denoiser;
procedural textures only (no image files, no random numbers); the PNG writer zeroes the colour of
fully transparent pixels and compresses deterministically. Glowing materials are not sampled as
lights (`emission_sampling = "NONE"`): with it, two renders of the same scene differed by a few
levels on some pixels. Two full runs gave byte-identical files (checked with `sha256sum`). Another
Blender version, or another CPU, may change pixels slightly; the version is pinned for that reason.

## Size budget

Budget: **2 MB** of PNG for all shipped graphics, so that the mod zip stays a few MB.
Measured on 0.1.40 (`find graphics -name "*.png" -printf "%s\n"`, summed): 33 files, 703 840 bytes
(about 0.70 MB, a third of the budget); the hub's and the teleporter's sheets and shadows (16 frames
each) are 484 365 bytes of it. The packaged mod zip of 0.1.40 is 974 087 bytes.

## Integration in the prototypes

`prototypes/graphics.lua` reads `prototypes/sprites.lua` and returns, for a model name:
`graphics.sprite(name)` (a still `Sprite` with the building and shadow layers, used by containers'
`picture` and the substations' `picture`), `graphics.animation(name)` (an `Animation` with both
layers, used by the hub's and the teleporter's `animation`, with `continuous_animation = true`) and
`graphics.icons(name)`, plus `graphics.vertical_extension(name)`: how far the render rises above the
selection box (measured by the pipeline, rounded up to 0.05 tile), which every rendered building
uses as its `drawing_box_vertical_extension`. The prototypes keep their collision and selection boxes; the 1×1 crates keep
the steel chest's circuit connector, which the crate is sized for. Space Age graphics are never
referenced. Which buildings keep base sprites, and why: [visual-identity.md](visual-identity.md#kept-base-sprites).

## Check

`spec/graphics_spec.lua` (part of `.lua/bin/busted`, see [testing.md](testing.md)) fails when:

- a `__galactic-bazaar__/...` path named in `prototypes/` does not exist;
- a sheet's PNG size is not the declared frame size times its frames per row and rows
  (`line_length` 0 or absent: one row);
- a frame of a building or shadow sheet is cut off: the spec decodes each PNG
  (`spec/support/png.lua`, a small inflate and unfilter in Lua, no Blender needed) and requires the
  outermost rows and columns of every frame to be fully transparent, which the pipeline's 1-pixel
  crop margin guarantees for an uncut render;
- an icon is not 64 px with four mipmaps (120 × 64);
- `graphics/` holds a file that `prototypes/sprites.lua` does not name.

The render itself refuses a cut: `render.py` sizes each canvas from the model's highest and farthest
points and the sun's angle (a point at height z casts its shadow z / tan 40° away), with half a tile
to spare, and stops with an error if a render still touches the canvas edge.

The FactorioTest runs load the prototypes (a malformed sprite table fails there), but the headless
server is not known to load the image files themselves: the spec above and the in-game check below
are what cover the files.

## Checking in the game (vanilla, Windows)

Deploy (`python3 tools/build.py deploy /mnt/c/Users/<you>/AppData/Roaming/Factorio/mods`), start a
map, run `/c game.player.force.research_all_technologies()` (disables achievements for that save),
and place each building beside a steel chest and an accumulator. In order of risk:

1. **Shadows**: no hard vertical cut; same direction, length and darkness as the base buildings'.
2. **Wire ends**: connect a red wire to each crate (export, import, contract, docking bay, catapult,
   vault uplink, warehouse); the connector and wire end sit on the crate, not in the air.
3. **Alt-mode icons and alerts**: with alt mode on, and with a building stopped (no hub in range),
   the icons sit on the building, not beside it.
4. **Animations**: the hub's dish sweeps back and forth, the teleporter's emitters turn and its
   core pulses, with no jump at the loop; both also run unpowered.
5. **Icons at small size**: inventory, quickbar, tech tree, the Galactic Bazaar button; export and
   import (arrow up or down) and the two substations can be told apart without colour.
6. **Night**: glowing parts are only painted bright (no light layer); say whether one is wanted.
